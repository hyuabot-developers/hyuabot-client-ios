# UI/UX verification

This change covers F-01–F-11 in the approved UI/UX handover. The following checks describe what to inspect on an installed app; they do not imply a production device check.

| Area | Check on iOS |
|---|---|
| Map (F-01) | Search a building and room. Confirm the result carries the map URL/sequence, then open it and check the marker/detail for the selected place. Empty map data shows an error. |
| Transit status (F-02) | Switch every bus and subway tab. Check loading, empty, offline/error and retry, normal `HH:mm` check time, scheduled rows, and stale server data (bus ≥120 s; newest train update per station ≥180 s). Future server times are normal. |
| Transit rows (F-03, F-05, F-09) | Confirm long names wrap, the follow-on ETA has its own line and actual target stop name, and dark/light text is readable. The bus settings footer appears only on the Seoul tab. Transit colors mark rows; low-floor badges and green filter buttons use dark foregrounds. |
| Today Home (F-04) | Scroll shuttle → optional location bus → all cafeterias. Check two shuttle departures, up to two transfers each, bus alternatives, scheduled candidates, bus 50 priority, and the two-leg Incheon/Sosa route details. The weather summary stays on one line; tap the visible Open-Meteo source link to open its full summary and source. Home settings stays in the header. |
| Home location (F-04) | Denied, missing, inaccurate, expired, or out-of-range location hides the bus card. Suwon uses 2,000 m; other stops use 1,500 m. Manual dormitory/Shuttlecock select fixed groups. Manual station/terminal/Jungang use a fresh fix on entry, foreground, and user refresh without changing the manual shuttle departure. |
| Cafeteria and calendar (F-06, F-07) | Swipe and tap cafeteria tabs in both directions; the selected tab and content must match. Check missing running time and selected-day empty calendar messages. |
| Settings (F-08) | Verify the system-language explanation and return from iOS Settings. |
| Timetable and coach marks (F-10, F-11) | Scroll the shuttle timetable to its final row; the top filter control does not cover it. Advance existing shuttle coach marks and reset the campus page marks. |

Local validation: `xcodebuild build-for-testing` and `test-without-building` passed on iPhone 18 Pro / iOS 27.0 (46 passed, 3 skipped). `ScreenshotCaptureUITests.testCaptureScreenshots` passed on iPhone Air / iOS 26.5. `xcodebuild -configuration Release -destination "generic/platform=iOS Simulator" build`, `swiftformat --lint .`, `scripts/run-swiftlint.sh`, and `ruby scripts/check-localizations.rb` passed after the final weather-detail adjustment. One cafeteria header snapshot mismatched its reference on iOS 26.5 while the same snapshot passed on iOS 27.0; the images appeared visually equivalent, and no 26.5 baseline was rewritten.

Visual environment: iPhone Air / iOS 26.5 and iPhone 18 Pro / iOS 27.0 simulators. Home, bus, subway, cafeteria, settings, and shuttle timetable screenshots were inspected; the final Home capture shows a one-line weather summary with the full rain-start time and a visible Open-Meteo source. iPad mini / iOS 26.5 was launched with the Home experience enabled; the home cards, transfer row, and cafeteria had no overlap. The full iPad screenshot test was interrupted because its first-launch location prompt blocked later tab captures; after granting simulated location access, the Home layout was inspected directly. The agreed 375×667 pt minimum was checked from layout constraints but not run on a device. Maximum Dynamic Type and real VoiceOver behavior still need a device check. 02:00–05:00 stale behavior and location edge cases require device or timed checks. New ko/en/ja/zh-Hans text is automatic translation without native-speaker review.
